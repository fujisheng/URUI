# RmlUnity Android APK using Unity Personal (no Pro license needed)

## Why we use two services

Unity Personal license activation is supported through **Unity Hub**; Unity does not support manually generating new Personal `.ulf` licenses for GitHub-hosted, disposable GameCI runners.

Instead, use:

1. **GitHub Actions** to cross-compile RmlUi and FreeType for Android ARM64.
2. **Unity Build Automation (UBA)** to build the Android APK on Unity's own managed build service, using the available Unity DevOps free tier.

Unity's 2026 DevOps free offering includes some build minutes and can be used with a Unity ID; check your organization's current usage and pricing before enabling auto-build.

## Phase A: publish Android native library (automated)

Open the private GitHub repo:

https://github.com/fujisheng/RmlUnity/actions/workflows/android-native.yml

The workflow **Publish Android ARM64 Native Plugin** runs when its YAML or Native/ sources change, or manually.

On success, the workflow:
- Compiles RmlUi 6.3 + FreeType 2.13.3 for Android arm64-v8a.
- Validates the ELF architecture, strips debug symbols.
- Commits `Assets/Plugins/Android/libs/arm64-v8a/libRmlUnityBridge.so` into `main`.
- Exposes a short-lived artifact `rmlunity-arm64-native-plugin` for debugging.

Make sure `Assets/Plugins/Android/libs/arm64-v8a/libRmlUnityBridge.so` exists on the current `main` branch **before** configuring Unity Cloud. Its `.meta` file has explicit Android/ARM64 import settings.

The native `.so` is **not** an APK and cannot be installed on a phone.

If the action fails while pushing the binary, open GitHub repository **Settings → Actions → General → Workflow permissions**, allow workflow `GITHUB_TOKEN` write access, and re-run manually. This permission is used solely to commit the compiled .so to this private repository.

## Phase B: connect private GitHub repository to Unity Build Automation (manual one-time setup)

1. On mobile or desktop, open https://cloud.unity.com and log in with your **Unity ID**.
2. Select or create a Unity Cloud project in your organization. Go to **DevOps → Build Automation**.
3. In Source control setup choose **GitHub** and connect only the private repository `fujisheng/RmlUnity`. A fine-grained GitHub Personal Access Token with **Contents: read-only** on that repository is sufficient for manual builds; if you enable auto-build, add the webhook permission requested by Unity.
   - Token creation page: https://github.com/settings/personal-access-tokens/new
   - Paste the token **only in Unity's secure authorization form**, not in a GitHub commit, Issue or chat.
4. Create a new Build Automation configuration:
   - Platform: **Android**
   - Target name: `rmlunity-personal-android`
   - Branch: `main`
   - Unity Editor version: **2022.3 LTS**, preferably exactly `2022.3.62f1` (as in ProjectSettings/ProjectVersion.txt).
   - Build output: **APK**, turn off `Build app bundles (.aab) instead of an APK`.
   - Architecture: ARM64 (hook configures IL2CPP/ARM64).
   - Builder: a supported Linux builder, if available in your organization.
5. In **Advanced settings → Script hooks → Pre-export method**, enter this exact method name:
   `RmlUnityCloudBuild.PreExport`

   This method, stored at `Assets/Editor/RmlUnityCloudBuild.cs`, validates the plugin, creates the demo scene, configures Scenes in Build, and sets PlayerSettings for IL2CPP ARM64 Android.

6. Set **Auto-build off** for the first attempt. Start **Build now** manually to avoid exhausting the free monthly build minutes on failed attempts.
7. After the build finishes, inspect **Build Automation → Builds → Artifacts**, download the APK and install it on an Android ARM64 device.

If the UBA configuration requires a Scene List before invoking the pre-export hook, specify `RmlUnity/Demo/RmlUnityDemo.unity` as the scene relative to `Assets/`, then verify it is generated by `PreExport`. The current repo generates the demo scene in the editor; it does not yet include a manually serialized Unity scene file.

## Important limitations / validation status

- Android RmlUi ARM64 C++ build: **previously compiled successfully** via GitHub Actions run #40625090580.
- GitHub Actions new native publish-to-repo workflow: check its latest run; an uploaded artifact alone does not confirm the .so was committed.
- Unity Build Automation actual APK: **not yet tested**. The owner must connect their Unity Cloud organization and GitHub repository first.
- Unity Editor C# compilation, Android packaging and appearance may expose additional issues; diagnose using the Unity cloud build log.
- Single-touch input only, partial CSS compatibility, incomplete high-end effects and no uGUI performance benchmark.
- No Unity license, GitHub token, Unity password or private key should ever be committed or pasted in chat.

## Fallback: self-hosted GitHub Actions runner

If the Unity free cloud quota is exhausted or Build Automation is not available for your account, use a Windows/Linux machine with Unity Hub installed and the Personal license activated for your own Unity account. You can then set up a GitHub Actions **self-hosted runner**, but must maintain its disk, Android SDK/NDK, and Unity Editor yourself, and comply with Unity licensing/automation terms. A GitHub-hosted Ubuntu VM does **not** inherit the Personal activation from your computer.
