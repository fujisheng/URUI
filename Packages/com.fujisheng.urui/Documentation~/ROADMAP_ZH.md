# 路线图

URUI 的方向是让人和 AI 能通过文本理解和迭代 Unity UI，同时由 C# 保持清晰的游戏业务边界。

当前可用范围见[支持矩阵](LIMITATIONS_ZH.md)。以下是后续规划方向，尚未实现或完成验证，不作为当前功能承诺，也没有确定的发布日期。

| 方向 | 后续工作 |
| --- | --- |
| 平台兼容 | 逐项验证已构建插件的 Unity Player/设备运行；再评估 Linux、iOS 模拟器等目标 |
| 可选框架适配 | 后续可基于 Name/Parent、层级、样式与订阅编写独立 FUI 适配器；当前无依赖或数据绑定实现 |
| 渲染管线 | 评估并接入 URP/HDRP，分别验证相机、绘制时机和图形后端 |
| 输入与控件 | 扩大真实系统 IME、移动端软键盘、设备触摸与无障碍验证；当前已有键盘、文本编辑、焦点导航、同步事件和常用控件 |
| 文档与资源 | 完善字体、图片及外部样式资源的加载方式与诊断 |
| 开发体验 | 评估文本变更预览、热重载和界面调试工具，缩短修改到检查的反馈过程 |
| 质量与性能 | 扩大自动化功能覆盖，建立可复现的场景与平台性能测试 |

跨平台支持需要逐项构建与运行验证，RmlUi 自身支持的平台不等于 URUI 已经支持的平台。完整浏览器与 JavaScript 运行环境不属于当前产品目标。
